Project overview

Build a premium, light-mode portfolio website for Ginger Studios & Creatives, a photography and videography studio based in Abeokuta, Nigeria, shooting weddings, portraits, birthdays and brand films. The site must feel cinematic, warm and bespoke — not like a template. It also needs a client gallery delivery system: photographers upload a client's shoot, the system generates a private, time-limited link the client can use to view/download their photos, with an option to save the gallery straight to their own Google Drive.

Tech stack
Frontend: React (Vite), Tailwind CSS, Framer Motion for all animation/transitions
Routing: React Router
Backend: Node.js + Express
Database: PostgreSQL (Replit DB or Neon) — stores galleries, images metadata, client links, expiry dates
File storage: Cloud object storage for images/video (Cloudinary or Supabase Storage — pick one and wire it up; do not store binary files in Postgres)
Auth: Simple admin login (photographer/studio owner) via email+password, sessions with JWT or cookie-session
Google Drive integration: Google Drive API (OAuth 2.0) so a client can click "Add to my Google Drive" and authorize a copy of their gallery into their own Drive
Email (optional but recommended): Send the client their private gallery link by email when a shoot is uploaded (Resend or Nodemailer)

Site structure / pages
Home — hero (above), then a curated "Selected Work" masonry/grid section mixing photo and video thumbnails (click to open a lightbox/modal with Framer Motion shared-layout transition), a services strip (Weddings / Portraits / Birthdays / Brand Films), a short studio story section, testimonials carousel, and a footer with contact + socials.
Photography — filterable gallery (Weddings, Portraits, Birthdays, Events) with smooth filter transitions.
Videography — video reel grid, each opening an inline player.
Client Gallery Access (/gallery/:token) — the page a client lands on via their private link:
Validates the token server-side and checks expiry (3 months from upload date).
If valid and not expired: shows a clean gallery of their photos, a "Download all" (zip) option, individual image download, and an "Add to my Google Drive" button that triggers Google OAuth and copies the images into a folder in the client's own Drive.
If expired or invalid: a clear, on-brand message explaining the link has expired, with a contact CTA to request a re-send (no vague error, no dead end).
Admin dashboard (/admin, login-protected):
Create a new client gallery: upload multiple images (and optionally a video), name the client/shoot, set/confirm the 3-month expiry (auto-calculated but editable), and generate the shareable link.
List of all client galleries with status (active/expiring soon/expired), view count, and a way to revoke or extend a link.
Copy-link and "resend email" actions per gallery.
Client gallery delivery logic (core functionality — be precise here)
Each gallery record: id, clientName, shootTitle, imageUrls[], createdAt, expiresAt (createdAt + 90 days), accessToken (random, unguessable, URL-safe), viewCount.
The public /gallery/:token route looks up by accessToken, not by database id, and never exposes the studio's admin routes.
On expiry, do not delete the underlying files immediately — just block public access and show the expired-state message; let the admin decide whether to extend or delete.
Google Drive "save" flow: client authorizes read/write to their own Drive via OAuth consent screen scoped only to drive.file (not full Drive access), server creates a folder named after the shoot, and copies the images in.
Motion & interaction rules
Use Framer Motion for: hero entrance stagger, phone swipe/autoplay transitions, gallery lightbox open/close (shared layout animation), filter-tab transitions, scroll-triggered reveals for sections below the fold (whileInView), and hover micro-interactions on buttons/cards.
Respect prefers-reduced-motion — fall back to simple opacity fades.
Keep animation purposeful and restrained outside the hero; the hero is where the "wow" budget gets spent.
Responsiveness & quality bar
Fully responsive down to small mobile screens; the phone-mockup hero should gracefully become a centered, slightly smaller phone with the copy stacked above it on mobile.
Visible keyboard focus states throughout.
Fast image loading (lazy-load below-the-fold images, optimized/responsive image sizes).
